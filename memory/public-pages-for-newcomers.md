A public page (results site, stakeholder page) is for a reader who knows nothing about the project. Before any
result, it says what the task is, what the agent or system does step by step, and what each score means, with a
real example. Internal labels such as milestone names (M1, M2, M3) or config slugs never appear on it.

**Why:** Bhavya, 2026-10-11, on the first reflective-qa results page: "It doesn't describe the problem very well,
what the agent is doing, what the scores mean. M1, M2, M3 mean nothing to the reader."
Bhavya repeated it for the README on 2026-10-11: "ensure it's clearly written and not use abbreiviates like M1, M2".
**How to apply:** For any page or write-up shared outside the session, order it as: the answer in one paragraph,
then the task, the method, how it is scored (on a real example), the results, and the limits. Give each internal name
a plain name. Related: [[reflective-qa-project]], [[user-profile]].
